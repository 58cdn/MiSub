## HTTP(S) 节点

页面、外部 API、Probe 清单、导入、排序、刷新与订阅输出共用 `shared/subscription-kind.js`：

- HTTP(S) URI 同时具有用户名、密码、主机和显式数字端口，且路径为 `/` 时，可识别为手动代理节点。查询参数只允许转换器使用的 `sni`、`peer`、`allowInsecure`、`insecure`、`fp`、`alpn`；支持 IPv6、编码凭据、片段名称及显式默认端口。
- 带非根路径或其它查询参数（如 `token`）的认证 URL，以及普通 HTTP(S) URL，仍是远程订阅源。
- 手动节点不会进入订阅刷新与流量通知队列；导入、手动排序及订阅组引用不会重复添加同一 HTTP 节点。
- 历史订阅组若在 `subscriptions` 中引用 HTTP 节点，预览和下载仍可使用它；同时出现在 `manualNodes` 时按 ID 去重。此行为不写回或迁移保存的数据。

**待真实数据核对的歧义：**带凭据、显式端口且仅根路径、查询为空或仅含上述协议参数的 URL，也可能是 Basic Auth 订阅源。当前沿用上游的节点形态推断；在合入前应确认是否存在这种订阅。若存在，需另行设计显式类型及兼容策略，不能仅靠 URL 无歧义判断。未提供凭据的 HTTP 代理端点也保持订阅类型，不据端口猜测为节点。

## Mihomo 链式代理

- 前置组只保留原始节点成员，移除动态成员选项；原有成员全部为策略组时，以原始节点集合填充，阻断间接引用形成的环路。
- 落地副本名称避开原始节点、现有策略组和本批链式声明将创建的策略组名称。
- 声明的前置组或落地组与原始节点重名时忽略该声明，避免产生重名组。
- 未声明链式代理的模板不受影响；非 Meta 客户端仍使用普通策略组，不输出 `dialer-proxy`。

这些规则限制新生成的链式连接；不承担修复输入配置本身已有的 `dialer-proxy` 环路。
