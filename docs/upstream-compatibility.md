## HTTP(S) 节点

页面、外部 API、Probe 清单、导入、排序、刷新与订阅输出共用 `shared/subscription-kind.js`：

- 保存的 `type` 明确区分 `subscription` 和 `manual_node`。同一个 HTTP(S) URL 可以分别作为订阅源和手动代理，不因凭据、端口或协议参数改变用户选择。
- 没有 `type` 的历史 HTTP(S) 记录继续作为订阅源，与二开 main 的既有行为一致；不根据用户名、密码、ID 前缀或根路径推断为代理。历史非 HTTP 节点仍按节点协议识别。
- 显式手动 HTTP(S) 节点需要主机、显式数字端口及根路径 `/`，用户名和密码可选。查询参数只允许 `sni`、`peer`、`allowInsecure`、`insecure`、`fp`、`alpn`；支持 IPv6、编码凭据、片段名称及显式默认端口。不满足节点格式时拒绝输入，不自动改为订阅源。
- 订阅表单及订阅 API 保存 `subscription`；手动节点表单及节点 API 保存 `manual_node`。API 类型由所用端点确定，编辑 URL 时保留该类型。
- 通用文本批量导入及 Telegram 文本中的 HTTP(S) 链接默认作为订阅源。HTTP 代理通过手动节点入口或节点文件导入；手动节点多行输入保留手动类型。结构化配置解析出的节点保存为 `manual_node`。去重同时比较类型和 URL。
- 手动节点不会进入订阅刷新与流量通知队列；导入、手动排序及订阅组引用不会重复添加同一 HTTP 节点。
- 已明确为手动节点的 HTTP 记录若在历史订阅组的 `subscriptions` 中被引用，预览和下载仍可使用它；同时出现在 `manualNodes` 时按 ID 去重。此行为不写回或迁移保存的数据。

类型保存在现有 KV/D1 JSON 记录中，并纳入原子编辑及刷新身份校验。修改类型后，旧身份的异步刷新结果不能写回。无需 D1 schema 或绑定变更，不执行历史数据回填。导入旧备份时，没有类型的混合集合 HTTP 记录仍按上述兼容规则处理；旧格式中单独的 `manualNodes` 集合明确表示手动节点，合入统一集合时保留该类型。

## Mihomo 链式代理

- 前置组只保留原始节点成员，移除动态成员选项；原有成员全部为策略组时，以原始节点集合填充，阻断间接引用形成的环路。
- 落地副本名称避开原始节点、现有策略组和本批链式声明将创建的策略组名称。
- 声明的前置组或落地组与原始节点重名时忽略该声明，避免产生重名组。
- 未声明链式代理的模板不受影响；非 Meta 客户端仍使用普通策略组，不输出 `dialer-proxy`。

这些规则限制新生成的链式连接；不承担修复输入配置本身已有的 `dialer-proxy` 环路。
