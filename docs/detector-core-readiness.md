# 检测器本机就绪握手设计

检测器启动必须在请求真实节点前确认代理核心能处理 HTTP 入站及路由。控制接口和监听端口可达分别说明接口可响应和端口已监听，不能单独表示核心初始化完成。

## 本机闭环

启动器为每次启动生成随机标识，在 127.0.0.1 临时监听一个严格限定用途的 HTTP 代理 fixture。核心配置为该随机 `.invalid` 域添加唯一 DOMAIN 路由，指向此本机端点；所有其他目标仍由 `MATCH,probe-target` 处理。端点不解析地址、不建立出站连接、不转发请求。

启动器通过带认证的核心 HTTP 入站发送专用请求。端点仅接受准确的 CONNECT authority、隧道内 GET 的 Host/path、认证和无请求体约束，返回随机标识的固定长度响应。成功必须同时核对完整响应和端点确实处理了本次请求；CONNECT 200 不作为就绪证据。

整个握手共享原有 10 秒启动预算。重试仅针对本机专用请求，不请求真实节点、不计为节点延迟。认证、随机域、路径和标识由程序生成，不包含订阅或节点凭据。客户端固定核心代理、禁用环境代理及重定向，限制响应大小；监听器限制并发、头部、读取与写入时间。成功、失败、取消和进程退出均关闭监听器及所有连接。

本机端点关闭后，专用路由无法转发任何目标。普通诊断请求继续只经过所选节点；没有 DIRECT 路由或外部回退。

## 验收

- 控制接口和代理端口先就绪、隧道后就绪的可重复 fixture：完整 nonce 握手前不得返回客户端。
- 拒绝不匹配的身份、authority、Host、路径、方法、请求体、过大响应、重定向及直接伪造成功；不转发任意目标。
- 验证共享超时、取消、核心退出、连接收尾和并发上限，确认未发送任何真实节点请求。
- Linux/macOS/Windows 原生 race、真实内核路由及 TLS 证书拒绝测试全部通过，保持现有断言及超时。

实现通过独立审查及最终 HEAD CI 后合并，并重新运行主分支集成验收；实际发行和网页目录启用分别记录。
