## 实际表单的八组操作

编辑、保存、删除、拖拽、通知已读和退出均由真实 DOM 控件发起；Pinia 只用于读取断言。数据库验证提交结果，处理器完成后才暂停/丢弃响应，提交前 503 则另行注入。

1. 来源新增、改名、删除并逐次保存，四条原来源、隐藏手动节点和组引用完整保留。
2. 保存 ACK 暂停期间再次编辑，并打开通知标已读；已提交内容确认，后续编辑仍单独保存。
3. 提交响应丢失后编辑另一来源并重试，复用 payload/operationId/收据，后续编辑保留 dirty。
4. 提交前 503、没有新编辑的重试成功清除未保存状态；通知仍可使用。
5. 进入排序时显示全部四条来源并禁用筛选/搜索，拖拽后重载验证完整顺序及隐藏引用。与 #48 的完整集合排序语义一致。
6. 通过实际订阅组表单修改并保存，禁用来源和手动节点关联保留。
7. 两个共享 Cookie 的标签编辑同一来源，旧版本保存冲突保留编辑，显式 Discard 才载入服务器版本。
8. 保存 ACK 暂停后退出，私有集合清空；legacy Cookie 删除，d1-v1 服务端鉴权为 false。释放旧 ACK、重载和重新登录，不恢复旧 dirty 状态。

这些场景覆盖基本增删改、排序、保存和会话交错；高级规则、UA、拉取代理、流量等全部控件矩阵没有宣称完整验收。

## Cookie 响应交错与生产边界

历史 legacy 组合 `1ba4208ff776b996863f2a08f1a4379198fee77f` 的 7 组观察复现了迟到 login/GET 续期恢复退出 Cookie，以及迟到 logout 删除新 Cookie。该证据是漏洞复现，不是修复通过。JS 响应代次不能撤回浏览器已接受的 HttpOnly Set-Cookie。

#40 已实现[持久会话与退出恢复](session-authority.md)：pending SID 必须实际 Cookie 确认；续期及退出不下发 Set-Cookie，清理只删除不再复用的失效名称，固定收据及服务端撤销支持多标签和失败重试。新协议默认关闭；生产 legacy 模式仍有旧风险，需按[启用决定](session-activation-decision.md)执行才能验收生产修复。

本地 SQLite 不等于真实 D1，合成 Chrome 不等于实际 Pages 响应链或 Safari。来源 IP 信任、目标绑定、跨 isolate、生产容量、用户浏览器、真实设备和节点仍分别保留验收记录；没有用生产 `/api/data` 获取证明。
