## 实际表单路径

全部编辑、保存、删除、拖拽、通知已读和退出动作由 DOM 控件发起。Pinia 只用于读取断言；数据库直接读取验证已提交结果。受控响应在真实处理器完成后暂停或丢弃，503 在提交前注入。

1. 在 Sources 页面新增来源、修改名称、删除新增来源并逐次保存；原有四个来源、隐藏手动节点及订阅组引用完整保留。
2. 保存已提交但响应暂停时，再次打开编辑表单修改名称；期间打开通知并标已读。第一响应只确认已提交内容，后续编辑仍可单独保存。
3. 已提交响应丢失后继续编辑另一个来源，再点击重试。请求 payload、operationId、收据和版本保持相同，`replayed=true`；后续编辑保留 dirty，下一次保存才提交它。
4. 提交前 503 后没有新编辑，点击重试成功即清除未保存状态。通知接口仍可使用。产品失败处理只标记未保存，不将传输失败计为新编辑代次。
5. 在 disabled 状态筛选下实际拖拽两条来源，只变更可见位置；清除状态筛选后输入名称搜索，进入排序会显示全部四条来源并禁用搜索。再次拖拽、保存及重载核对完整顺序，隐藏节点和组引用仍保留。
6. 实际打开订阅组编辑表单、修改名称、保存和重载；禁用来源引用与手动节点关联保持完整。
7. 两个共享 Cookie 的标签编辑同一来源：先保存者成功，旧版本标签得到冲突并保留本地编辑；通知仍可用，显式 Discard 加载已提交版本。
8. 保存已提交但响应暂停时点击退出；确认私有集合清空、Cookie 删除。释放旧保存响应后重新登录，加载已提交权威数据，不恢复旧 dirty 状态。

这八组只针对基本增删改、排序、保存与会话交错。高级规则、UA、拉取代理测试、缓存、流量选项、website/notes 等全部控件矩阵尚未操作；不宣称整个编辑器所有控件验收。此轮 11 次外部字体请求均被阻断，后端出网、KV 写入、页面异常均为 0。

## Cookie 响应交错与上线阻塞

独立审查在固定组合 `1ba4208ff776b996863f2a08f1a4379198fee77f` 上运行真实登录/退出处理器和浏览器 Cookie，并对普通响应调用真实 `renewAuthSession`。本轮订阅保存的一行修复不改变这些认证文件。没有运行完整 Cloudflare Pages middleware，不把 localhost 当平台等价证明。

| 控制顺序                                                                    | 观察结果                                                           |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 同页或双标签：旧 login 成功响应暂停 → logout 完成 → 旧 login 到达           | HttpOnly Cookie 恢复，受保护 GET 200；同页 UI 仍退出，刷新后又登录 |
| 同页或双标签：旧 logout 清 Cookie 响应暂停 → 新 login 完成 → 旧 logout 到达 | 新 Cookie 被清除，受保护 GET 401；另一处 UI 可能仍登录             |
| 普通 GET 为 8 天旧合成 token 生成续期响应并暂停 → logout 完成 → 旧 GET 到达 | 续期 Cookie 在退出后恢复，受保护 GET 200                           |
| 仅测试 harness 使用同源 Web Lock，分别串行 login→logout 和 logout→login     | 两种认证请求对的 Cookie 最终顺序正确；另一个标签的 UI 仍可能陈旧   |

共 **7 个观察/对照场景成立，属于缺陷复现，不是产品修复通过**。12 次外部字体请求全部阻断，后端出网、KV 写入、页面异常均为 0；未保存 token/Cookie 原文。源报告为 `cookie-response-order.json` 和 `cookie-response-order-review.md`。

页面会话代次可以丢弃旧 JS 响应，却不能撤回浏览器已经接受的 HttpOnly Set-Cookie。单纯串行 login/logout 也管不到此前发出的普通续期响应，因此该问题保留为上线阻塞。本轮没有加入局部认证锁或改变安全库 schema。

需要先准备可审查的会话设计：

- 客户端协调应覆盖认证请求实际完成顺序、排队时登记意图、非秘密的跨标签失效通知、异常/关闭/不支持锁的兼容行为。
- 若要求退出后旧 token 不能重新获得权限，需要明确服务端撤销/会话代际、当前浏览器或全设备范围、存储故障和旧 token 兼容语义。不能临时复用登录安全事件或业务库，也不能全局换 secret 代替一次退出。
- 服务端撤销不会自行阻止迟到的旧清 Cookie 响应删除新 Cookie；普通响应滑动续期若改成显式端点，也要独立验证兼容和在途请求。

这与新登录限流、通知事务及订阅原子写入是不同边界。安全库和业务库隔离通过，不代表退出撤销保证通过。
