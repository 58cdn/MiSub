# 节点检测与多地域检测器

入口在手动节点页的“节点检测”。“选择节点”复用原列表勾选状态；“检测选中”只发送选中的节点；“检测全部”跨越分页并包含已禁用节点。界面使用点击时的节点快照，因此新编辑但尚未保存的节点也可以测，不改写原始订阅或节点记录。

## 操作顺序

1. 进入“设置 → 数据与集成 → 添加 / 管理检测器”，创建一台带地点名称的检测器，下载一次性私密 `probe.json`。
2. 按 [独立检测器说明](../detector/README.md) 下载匹配 Linux/macOS 与 CPU 的单文件包，在该机器上用普通用户启动。
3. 返回管理页，确认该检测器的最后通信（领单或心跳）。再到节点页选择节点、检测类型和一个或多个地点，确认节点凭据授权。
4. 需要测速时单独勾选流量授权。界面显示包含三个尝试的最坏读取预算，不超过 1 GiB；实际网络计费还包含协议头和缓冲。
5. 查看任务进度和逐节点、逐地点结果。可取消未完成部分，或在提交请求超时后重试原批次。

每个请求最多 500 个节点、8 个检测器、1 MiB JSON。界面还按 768 KiB 自动切分，单次最多 20 批；整体下载预算不会被分批绕开。已经创建的批次保留，未完成提交用同一个幂等键重试。关闭面板停止轮询，不取消已提交任务；离开页面不会继续派发尚未提交的批次。

“当前页全选”和“检测全部”不是同一件事。多个地点组成节点×检测器矩阵：每个地点都测试该批节点，而不是随机分配不同节点到不同地点后混成一个延迟。结果分页每页 200 条；当前页可以筛地点并按该地点的代理延迟排序。不同地点或不同时间的结果不代表本机连接质量。

## 管理检测器

“添加 / 管理检测器”默认使用卡片，可切换为表格并选择显示列；名称与操作列始终保留。当前站点的浏览器会记住视图和列选择，搜索条件、检测器数据与凭据不存入这些偏好。移动端保留手动选择的表格视图，表格可独立横向滚动，搜索、筛选和翻页按钮保持在表格外。

输入关键词后点击“搜索”或按 Enter，按名称、版本或平台匹配文字片段。可筛选在线、离线、未知或已撤销状态，以及常用列表、已删除或全部检测器。排序与分页由服务端处理，匹配数量覆盖筛选后的完整集合；默认按创建时间从新到旧显示，每页 20 台。表格支持点击可排序列标题切换方向，版本按文本排序。提交搜索或修改筛选、排序会回到第一页。

管理页分别展示最后通信、最近任务创建和最近结果回传时间，并提供七天内的分页检测记录。在线仅表示服务器在两分钟内收到通信，不代表节点可用；从未通信显示未知，刷新失败显示状态待刷新。版本和平台仅展示实际上报值；独立心跳时间与能力尚未持久记录时明确显示未知，不从版本或最后通信推断。

撤销前需确认；撤销会取消未完成任务，已有记录按保留期限保存。已撤销的检测器提供“删除”：确认后将其从常用列表隐藏，并保留检测器身份、历史和任务归属。若仍有活跃任务租约，页面会提示等待并刷新核对后手动重试。

在可见性筛选中选择“已删除”，可查看记录或确认“恢复”。恢复只让检测器重新显示，凭据仍然已撤销，历史的七天保留期限也不延长。要重新连接，请重新配对以创建新的检测器身份。详见[管理说明](detector-management.md)和[列表与恢复说明](detector-list-archive.md)。

## 六类结果

- `format`：MiSub 解析与必需字段检查；无 D1、无检测器也能运行。不等于节点在线。
- `tcp`：检测器到公开节点 IP/端口的 TCP 建连。原生 UDP 协议返回不适用，不因此取消真实代理测试。
- `proxy`：经指定节点访问固定 HTTPS 204 地址，测量完整请求耗时，不冒充 TCP RTT；无 DIRECT 回退。
- `speed`：经指定节点读取限量下载内容，记录字节和 bytes/s；默认 5 MiB、最多 20 MiB/次，不自动开启。
- `unlock`：八个服务的网络侧地区/可用性证据。普通 200/401 只显示“可访问，解锁未知”；明确地区拒绝、限流、验证码和未知分别处理。不测试账号套餐、不登录、不保证真实播放。
- `observations`：独立出口 IP、国家与可选的实验性 IPPure 质量证据，保留各来源时间、错误、未知值与冲突。IPinfo 当前未配置；来源请求耗时不作为节点延迟。详见[来源说明](probe-source-observations.md)。

失败、未知、不支持、未执行、取消不能显示为成功。关闭 TLS 验证、额外路由/次级目的地及未安全支持的传输参数明确返回不支持；不能悄悄改写配置后声称测试原节点成功。

## API 与开发

[OpenAPI 3.1](./node-probes.openapi.yaml) 是本功能接口文档，命名空间 `/api/probes/v1`，不复用 External Management API 的全局权限 Token，也不替换 `/api/nodes/diagnostics` 的单节点诊断接口。

管理端使用现有 `auth_session` Cookie；所有写请求必须携带精确同源 Origin。检测器只持有自己可撤销的 Bearer Token，不能调用管理端接口；检测器请求不允许 Cookie 或 Origin。不要把 Token 放进查询字符串、命令行参数、浏览器持久存储或日志。

管理端：`GET capabilities`、`POST format`、`GET/POST agents`、`GET agents/overview?offset=0&limit=20`、`GET agents/:id/history?offset=0&limit=20`、`DELETE agents/:id`、`GET/POST jobs`、`GET jobs/:id?offset=0`、`POST jobs/:id/cancel`。

任务范围支持 `scope=all`（已保存的全部手动节点）、`scope=selected` + `nodeIds`、`scope=snapshot` + `nodes`。最后一种可以供已解析订阅节点的调用方使用；当前面板入口在手动节点页，不会在点击“全部”时自动拉取全部订阅源。创建任务必须有 `consent=true` 和 `Idempotency-Key`；测速还要求 `options.allowMetered=true`。

检测器：`POST agent/claim` 领取一条或得到 null；`POST agent/tasks/:id/heartbeat` 续租；`POST agent/tasks/:id/result` 回传全部已请求检测项。服务已执行/声称通过的结果必须包含全部已请求服务。原始错误、响应正文、完整节点配置都不属于结果 DTO。

任务租约 90 秒、检测器每 20 秒续租，失去续租立即停止当前内核。最多三次尝试；任务 24 小时有效，记录保留七天并在后续 API 活动时清理。相同身份只能有一条有效租约；过期租约、跨检测器、取消/撤销后的回传全部拒绝。任务完成或取消时删除任务中的连接凭据副本。

## 部署边界

业务数据继续使用原来的 `MISUB_KV` / `MISUB_DB`。任务系统使用独立 `MISUB_PROBE_DB` D1；不能把高频租约写回一个 KV 全量 JSON。新库按本功能 schema 懒初始化，不迁移原始订阅表。

没有此绑定时显示提示，只允许格式检查。独立检测器的轮询、心跳和结果会产生 Pages/D1 请求、读写和节点流量；按部署数量核对账户额度。运行时无需公开探针端口，检测机需要访问 MiSub、节点及测试目标，而不是只允许访问 MiSub 一个域名。

## 验证命令

```sh
node --test tests/probes/*.check.mjs
npm test -- --run tests/unit/node-probe-panel.test.js
npm run test:run
npm run build
cd detector
go test -race ./...
```

源代码环境没有 `embedded/kernel.gz` 时，两个真实内核测试会明确跳过。发行 CI 四个原生平台必须提供校验后的内核并设置 `MISUB_PROBE_REQUIRE_KERNEL=1`，不允许跳过，且运行生成二进制的 `--self-test`。

真实用户节点的地区/服务结果必须由用户自己的检测器执行才能验收；CI 的受控代理夹具不是这些节点的替代证据。
