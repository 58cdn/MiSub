# 持久会话与退出恢复

`SESSION_AUTH_MODE=d1-v1` 启用实际认证路由和浏览器协调器。启用后仅接受专用 `MISUB_SESSION_DB` 中有效、已确认的会话；原 `auth_session` 签名 Cookie 不再获得管理权限。未设置此模式时继续使用原认证方式，因此部署代码本身不能代表生产 Cookie 问题已修复。

## 请求与浏览器行为

- 浏览器在首次登录请求之前登记共享意图。IndexedDB 保存取消能力和公开 ID，不保存密码或会话 bearer；localStorage 的随机退出代次防止协议查询或 IndexedDB 打开过程中的迟到登录继续执行。存储不可用时，新模式拒绝继续登录。
- `POST /api/session/prepare` 验证管理员密码并返回短期票据及 HttpOnly 操作 Cookie；`POST /api/login` 再次验证密码后创建待确认 SID。`POST /api/session/confirm` 必须同时持有票据与实际 SID Cookie，才能激活会话。
- 登录安全功能启用时，两处密码入口共同计入限流。有效票据创建待确认 SID 后，安全库以该 SID 幂等复查锁定、记录一次准入审计及消费一次提醒，然后才允许发送 Cookie。同一票据仅在两分钟内重试，返回原提醒（包括空提醒），不补发 Cookie、不重置新失败。旧会话的固定替换目标保存在待确认 SID 中，直到新 Cookie 确认才撤销，因此安全库拒绝或故障不提前退出旧会话。
- 登录审计表示服务端已批准签发，不保证客户端收到 Cookie 或完成激活；会话库与登录安全库没有共同事务。任何提交结果不明都不发 Cookie，客户端取消该 pending 操作后重新登录；已批准操作之后出现的新锁不追溯撤销该操作，退出撤销始终优先于迟到确认。
- SID 使用随机且不复用的 Cookie 名称。服务端续期只更新持久状态，不发送 Set-Cookie。会话空闲期限为30天、绝对期限为90天，登录待确认期限为2分钟。
- `POST /api/session/capture` 固定本次退出的实际 Cookie、已知 SID 和票据范围。短期缓存保证同一请求重放不扩大范围；签名收据支持缓存回收后继续重试。
- `POST /api/logout` 必须提交签名收据和取消证明，只撤销其中固定目标；它不发送 Cookie。`POST /api/session/cleanup` 只删除已失效的不可复用名称，迟到删除不影响后来登录。
- 退出失败会保留恢复记录。刷新或其他标签仍受该记录约束；重新登录先恢复旧操作。没有可信服务器目标时返回409，不能宣称退出成功；只有用户再次主动登录，且服务器确认本地目标已不存在，才清理这批本地旧元数据并开始新登录。
- 变更接口要求 HTTPS、POST、JSON 及完全匹配的 Origin；状态查询使用 `GET /api/session/protocol` 和 `GET /api/session/check`，后者不读取订阅数据。

## 一致性与容量

专用 D1 中的单行文档通过 revision CAS 原子提交票据、SID 和撤销范围。每次鉴权与冲突重试均新建 `first-primary` 查询会话，避免读取落后的副本；参见 [D1 Sessions API](https://developers.cloudflare.com/d1/worker-api/d1-database/#withsession)。提交结果不明返回503，调用方保留同一收据重试。

文档上限256 KiB。每类最多256条，发行阶段将活动 SID、票据与短期捕获缓存分别限制到128条；捕获接近容量时返回429。捕获缓存保留到其创建时间的重放窗口结束，不能提前逐出；签名的固定范围收据不占用长期快照行。过期 SID 与无活跃 SID 的过期票据随后续变更回收。伪造或全部已失效的目标不分配捕获缓存。

收据签名密钥在专用数据库初始化时生成，只保存在该库。Cookie 只保存随机 bearer，数据库只保存其 SHA-256。缺少绑定、缺表、缺初始行、非法状态或存储故障均失败关闭，不创建表、不回退到业务 KV/D1，也不自动启用模式。

## 启用与恢复门槛

本代码不修改 Wrangler 绑定、生产变量或部署流程。生产启用仍需明确授权：专用安全 D1 的创建或选择、绑定 `MISUB_SESSION_DB`、执行 [独立 schema](schema/session-authority.sql)、配置模式，以及确认自动部署保留新绑定。不能复用业务库或 Probe 库。授权与绑定未核实前，不在生产执行这些操作。

先在隔离环境验证真实 D1、浏览器 Cookie、并发 CAS、跨标签、失败重试及容量，再安排生产强制重新登录。若与登录限流/安全事件功能组合，票据发行与登录验证必须共同受该功能的限制，不能新增绕过锁定的密码验证入口。

安全库不能直接恢复旧备份并继续认证：旧快照可能重新带回已撤销 SID。恢复必须经过独立授权，同时使所有旧 SID 失效并强制重新登录。只轮换收据签名密钥不会使已有 SID 失效。启用后也不能直接回退为接受旧 `auth_session` 的模式。

本地 SQLite 适配器与实际 Chromium 测试用于产品协议验证，不能替代真实 Cloudflare D1 或生产验收；生产历史4→3调查与此认证变更分别保留证据。
