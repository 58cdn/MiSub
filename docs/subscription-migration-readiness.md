这不证明外部没有自行初始化的 schema 1 数据库。如果只读盘点发现 schema 1，必须保留完整副本、epoch 历史、收据、所有业务域与 schema，停止当前计划，再根据实际布局和写入历史单独设计升级。不能删除元数据伪装成 legacy，不能用重置 revision、重建 epoch 或关闭保护触发器强行继续。实验性的 `model_` 表也不是运行时 schema 1。

## 离线计划的输入和输出

[规划器](../experiments/subscription-transactions/migration.js) 是无 I/O 的函数，不接收环境绑定、数据库对象、账户或网络地址，不执行 SQL。输入必须包含调用者已取得的完整三表物理快照：

- subscriptions / profiles：`id,data,created_at,updated_at`。
- settings：`key,value,created_at,updated_at`，包含所有 key，不能只提供脱敏设置 API 的结果。
- 明确的目标 authority 和新 epoch；二者是实例/历史标识，不是凭据。

支持仓库 [schema.sql](../schema.sql) 的列布局。时间为字符串或 null；省略时间按 null 核对，若目标实际有时间值就拒绝，不能用省略字段绕过检查。未知列、重复物理主键、非字符串业务 JSON、非法已保护设置/规则、悬空组引用、同 ID 不同内容，以及已带协议运行元字段的条目都拒绝。旧 main 数组和内容一致的独立行可合并，但物理时间不一致时停止等待明确决策。

输入在第一次 await 前复制。计划包含源摘要、业务目标摘要、三表物理目标 `targetRows` 及其摘要、数量和完整 SQL 列表。物理行按 SQLite BINARY 的 UTF-8 顺序排列，回读时三表分别按 id / key COLLATE BINARY 排序后比较摘要，包含非 BMP Unicode 键。业务 JSON 的未知字段按解析后的值保留；物理时间保留；所有 settings 行及其 value 原字符串保持不变。协议读取会固定 D1 authority，原 settings 中的 legacy storageType 字符串不获得切换权威库的能力。新增的内部代际/观测时钟字段属于明确初始化。

**计划、绑定参数和 targetRows 可能含订阅凭据及完整设置秘密，必须视作私密备份材料。** 不打印正文、不提交仓库、不上传公共 CI；公共报告仅记录合成数据或计数/必要摘要。

## 单次事务、重复执行与恢复

整个计划只能在**匹配源数据的隔离副本**上，以一次完整事务或一次 D1 batch 执行。不得逐句 auto-commit、拆批或把计划当任意空库导入器。D1 batch 的整批失败回滚语义见[官方说明](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。

1. 首条创建协议 epoch 表；已初始化或残留该表的目标立即拒绝，集合尚未变更。
2. 临时 CHECK guard 在同一事务内以 BINARY 双向比较三表全部原始行和行数，核对包含隐藏列的列名集合及单列主键。源有增删改、大小写/时间变化、JSON 空白变化或目标副本不匹配都会整体回滚；未知生成列也拒绝。
3. 展开并写入集合，保留物理时间；再比较完整物理目标，拒绝既有触发器等造成的意外修改。
4. 建立协议约束及元数据，最后移除临时 guard。settings 行不重写，保护触发器开始约束之后的旧写入。

执行约定：

| 情况                                 | 安全处理                                                                                          |
| ------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 计划生成失败                         | 零数据库动作；保留源，处理明确歧义后重新规划                                                      |
| 整批任意语句失败 / 未提交连接中断    | 原数据和 schema 回滚；重新核对原副本后可重试同一完整计划                                          |
| 已提交但响应丢失                     | 先只读核对完整 targetRows 摘要、schema 2、authority、epoch、revision 0 及协议对象；匹配才确认完成 |
| 对已初始化目标重复执行               | 明确拒绝且不改数据，不是自动成功/no-op；禁止重置后重放                                            |
| 成功后已有新业务提交                 | revision/摘要会变化，不能再当初始目标验证或重新迁移；保留新历史并单独核对                         |
| 曾将 DDL 前缀逐句提交 / 目标状态未知 | 不自动续跑或删表；丢弃仅用于演练的副本，从保留的原副本重建。线上目标需单独调查与授权              |

事务隔离让并发 legacy 写入要么先发生、使源检查失败，要么在迁移后被保护触发器拒绝；双迁移只有一个可初始化。该保证不等于生产 writer 已排空：旧部署仍可能访问其他 KV/旧库，外部消息及在途网络也不属于本事务。

本计划不复制其他表、索引、触发器、登录 KV 或 Probe/安全库。须从**完整隔离副本**开始，保留其他结构和数据并另行盘点。列和主键检查不代替完整 CREATE TABLE、类型、约束、collation、索引与触发器审计；它不会自动证明任意数据库结构与仓库完全一致。未知布局不静默适配；本工具不是生产执行器、跨库搬运器或 KV 导出器。

## 给用户决策的上线清单

| 决策         | 建议或明确待授权动作                                                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 权威存储     | 推荐业务 D1 作为唯一可写权威，使用其事务准入。已有业务 D1 先做隔离副本演练；KV-only 需另批独立业务 D1 和迁移。Probe / 登录安全 D1 不复用            |
| 资源与配置   | 先核实当前业务库和绑定。若 KV-only 或决定影子库切换，需批准创建一个指定业务 D1、绑定 MISUB_DB；是否复用现有库须由只读证据决定                       |
| 数据与开关   | 单独批准私密完整备份、目标库 schema/data 事务、authority/epoch、MISUB_SUBSCRIPTION_PROTOCOL=d1-v1 与 MISUB_SUBSCRIPTION_AUTHORITY；默认均不自动启用 |
| 维护与验证   | 批准维护窗口、全部旧部署/API/Cron/Telegram/在途 waitUntil 排空、离线差异确认、受控真实读写验收，再决定合并/部署和解除冻结                           |
| 回滚         | 批准回滚截止点和新写入处理。尚未开放新写入时可按已验收备份/绑定方案回退；开放后必须保留并协调新历史，不能直接覆盖旧备份                             |
| 独立登录安全 | #38 的 MISUB_SECURITY_DB、schema 和开关是另一套独立批准；不随订阅迁移自动创建或启用                                                                 |

KV 不提供本协议所需的跨 key 事务/CAS，不能靠读前检查或进程锁宣称等价；见 [KV 一致性与事务限制](https://developers.cloudflare.com/kv/concepts/how-kv-works/)。这不要求用户立即迁移：继续 legacy 是明确保留其并发限制的选择。

备份必须包含业务表、所有 settings、协议对象/收据/epoch，以及部署与绑定映射的非秘密元数据；恢复演练必须在隔离副本完成。浏览器 JSON/WebDAV 数据备份不能代替数据库级回滚材料。Time Travel 的保留窗口、bookmark 和可恢复范围须读取实际账户证据；restore 是生产写入，不可用作试探。[D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)不能替代完整副本与明确的新写入处置。
