## 现有登录待办与当前访问状态

| 对象              | 已知状态                                                         | 用户现在需要做什么                                               |
| ----------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------- |
| GitHub            | 本轮只读仓库、Issue、PR 请求成功                                 | 无需为本次离线工作重新登录                                       |
| Cloudflare 管理面 | 当前会话未核实登录和目标项目权限                                 | 等具体只读核查步骤；若实际遇到登录页或拒绝，再在既有渠道完成登录 |
| MiSub 用户浏览器  | #33 历史待办提过“浏览器登录仍需用户自行完成”；本轮未核实当前状态 | 不因历史记录重复要求登录；后续现场核查先列明页面及可能副作用     |
| 独立 WebDAV       | 当前登录、备份文件属性及历史完整性未核实                         | 如选择备份调查，使用用户已有独立只读渠道；完整下载另列范围       |

这里的“未核实”不表示登录失效，也不阻止仓库和离线工作。不要在报告、Issue 或 PR 中粘贴密码、Cookie、订阅原文和备份内容。现场取证优先使用脱敏计数/ID、绑定元数据及只读属性；不从 MiSub 设置提取 WebDAV 秘密，不运行可能创建目录的连接测试，不为探测登录而直接调用有初始化副作用的管理接口。

## 上线验收如何记账

1. 合并前对实际最终 HEAD 与依赖集成重验，遵守分支保护和他人审批要求，不自批准或绕过保护。
2. 分别记录代码/CI、Pages 发布、公开资产字节、用户浏览器、真实设备、真实节点的证据；其中一项成功不能替代其他项。
3. 本轮各草稿 PR 的 Pages 生产步骤为 skipped；没有执行生产备份、迁移、D1 创建、配对、服务安装或实网节点探测。
4. Cloudflare 实网验收必须包括实际 Cookie/来源 IP 信任、绑定故障行为、真实数据库事务边界和目标浏览器；localhost 合成数据不能替代平台确认。
