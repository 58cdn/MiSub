# 检测器领单声明与续租记录

检测器每次领取任务可上报版本化协议声明。服务端按当次请求判断任务兼容性，可分阶段保存声明和成功续租时间，在管理界面显示最近记录的领单声明。声明由检测器自报，不证明当前实际能力、节点连通性、服务解锁或内核执行；任务结果中的历史执行声明另见 [执行结果声明](probe-execution-metadata.md)。

## 协议与兼容性

新检测器同时发送新版 `capabilities` 和旧顶层 `observationsVersion`，旧服务端继续识别旧字段。服务端只保存固定字段，不保存任意客户端字段、配置、凭据或原始错误。

```json
{
    "version": "0.3.0-dev",
    "platform": "linux-amd64",
    "observationsVersion": 1,
    "capabilities": { "schemaVersion": 1, "observationsVersion": 1 }
}
```

示例版本仅用于说明协议。`schemaVersion` 是领单声明结构版本；`observationsVersion` 是已有来源证据协议版本，均不表示检测器发行版本。

| 当次请求                           | 声明状态             | 可领取 observations 任务 |
| ---------------------------------- | -------------------- | ------------------------ |
| 新结构合法，顶层缺失或严格为整数 1 | declared             | 是                       |
| 没有新字段，旧顶层严格为整数 1     | legacy               | 是，仅代表旧协议声明     |
| 两个字段都没有                     | missing              | 否                       |
| 新字段存在但结构/字段无效          | invalid_declaration  | 否                       |
| 新字段使用不支持的结构版本         | unsupported_schema   | 否                       |
| 新结构合法，但显式顶层版本与之矛盾 | conflicting_versions | 否                       |

不兼容声明仍可领取普通任务；包含 observations 的混合任务整体排除。所有运行模式共用这一兼容矩阵。调度只使用当次规范化请求，不读取持久化旧声明，也不从版本字符串、平台、历史结果或续租时间推断能力。

每次记录 claim 都完整替换声明，包括无任务可领取或已有活跃租约时。旧客户端重新领取会清除此前新版声明；成功续租只更新独立续租时间，不改变声明内容或接收时间。任务在关闭记录期间领取，随后启用记录时收到成功续租，可以创建“声明未知、只有续租时间”的记录。

## 默认关闭与阶段开关

`PROBE_AGENT_RUNTIME_MODE` 只接受以下值；未配置时为 `off`，显式非法值使相关能力读写请求返回固定 `503 probe_runtime_mode_invalid`。

| 模式   | 新表写入                 | 管理读取                                         |
| ------ | ------------------------ | ------------------------------------------------ |
| off    | 不查询、不写入、不建新表 | 保持 `capabilities:null`、`lastHeartbeatAt:null` |
| record | claim 与成功续租事务写入 | 保持旧返回契约                                   |
| read   | 同时写入                 | 返回经过校验的声明和独立续租时间                 |

新表为专用 `MISUB_PROBE_DB` 中的 `probe_agent_runtime_v1`，定义于 [独立迁移文件](../migrations/probes/0001_agent_runtime.sql)。它不属于默认初始化 schema，不会因管理员读取、检测器领取、普通发布或生产冒烟而自动创建。没有新数据库或身份配置要求，不涉及 `MISUB_DB`、KV、Cookie、会话或订阅数据。

启用记录后，联系时间、声明与领取租约在同一事务中提交；成功续租和续租记账也在同一事务中提交。缺表或写入失败返回固定 `503 probe_runtime_unavailable`，不会留下半份领取或续租。`read` 下读取失败也明确报错。撤销和取消仍使用原有表，可在新表缺失或模式配置错误时执行。

## 展示时间与未知状态

`capabilities` 的来源固定为 `agent_claim`。只有声明状态、协议字段和保存内容一致、接收时间为有效且不在未来的服务端时间，才返回声明视图；损坏或未知记录不回显原始内容。未记录、关闭读取、未来时间或存储记录不可识别时保持未知。撤销检测器不再显示能力声明。

`fresh` 仅表示截至该次查询，服务端在五分钟内收到过此记录：`0 ≤ checkedAt − receivedAt < 300000`。满五分钟为 `stale`。这一时间窗口独立于现有 120 秒在线状态，不表示当前实时能力；浏览器不会通过刷新显示时间、最近通信或当前版本补齐声明。`lastHeartbeatAt` 是最近成功续租时间，空闲领取不产生独立心跳记录。

## 激活审批与回滚

代码、测试、文档和未执行的迁移文件可作为普通 PR 审查合并；默认关闭不会增加新表访问。协调方负责汇总目标数据库、迁移及阶段开关的具体操作，提交用户确认，不能代替用户批准。生产操作须在取得各步骤实际所需的用户授权后，按以下顺序执行：

1. 用户确认目标数据库和迁移操作后，核对现有专用 `MISUB_PROBE_DB` 的身份及备份，在该检测库应用迁移文件；不创建新凭据或自动切换存储绑定。
2. 用户确认记录阶段激活后，将既有生产变量设为 `record`，确认新旧客户端领取、续租和错误路径正常，检查事务失败时租约不被授予。
3. 保持 `record` **至少完整五分钟**并取得用户对读取阶段激活的确认后，再切换到 `read`。读阶段包含写入，不能独立开 reader。

回滚时将模式设为 `off`，保留附加表和记录；旧代码不需要删除该表。每次关闭后重新启用，都必须重新经过 `record` 满五分钟再到 `read`，避免将关闭期间遗留的短期旧记录当作近期声明。直接 `off → read` 不属于支持的激活流程，单一模式开关不会自动追踪关闭区间。

部署脚本只保留项目中已经存在的合法明文模式值，不从 CI 环境变量启用或覆盖。`record/read` 要求已有检测库绑定；缺失绑定或非法配置会停止部署。设置为 `off`、缺省配置及其他生产设置保护保持有效。模式保留不执行迁移，也不证明 schema 已验收。

## 离线验收

Node 内存 SQLite、Miniflare 本地 D1、合成 HTTP、Go 假传输和 Chromium 模拟 API 覆盖完整替换、兼容矩阵、旧库关闭、启用缺表、同毫秒并发、失败回滚、撤销竞态、无效续租、旧租约切换、过期及未来时间。部署测试使用假 Cloudflare 与 Wrangler；不访问用户节点或生产数据。

接口字段见 [OpenAPI](node-probes.openapi.yaml)，生产操作的一般边界见 [部署说明](node-probes-deployment.md)。
