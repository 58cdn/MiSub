# 检测器草稿发行恢复

发行操作使用 GitHub Release ID 标识草稿。按 tag 查询接口仅用于已公开发行，不用于草稿验收。

## 新发行

创建草稿后取得并固定 Release ID，通过该 ID 读取并验证 tag、草稿状态及完整资产集合。每个资产必须与已验证的本地产物具有相同大小和 SHA256；公开操作也绑定该 ID。现有标签、发行或资产不覆盖。

## 显式恢复

恢复要求明确指定版本、原源码提交、原手动运行 ID 和草稿 Release ID。先确认原 canonical 工作流运行、tag 提交和仍未公开的草稿，再下载草稿的完整资产集合并验证实际字节、manifest、SHA256SUMS、目录、五目标证据和完整对应源码。对每个实际下载文件执行 GitHub 签名来源验证，约束原仓库、工作流、main ref、source/signer commit 及原运行身份。

只在全部门槛通过且最终重读 tag、草稿和资产未变时公开同一个 Release ID。恢复不重新构建、不重新上传、不修改标签或替换任何资产；部分失败保留现场并报告。恢复代码提交与原资产源码提交分别记录。

离线 fixture 覆盖草稿按 tag 404、按 ID 可读、缺项/多项/重复名/大小或摘要不符、版本或提交不符、已公开状态、来源证明失败及核验后状态改变。所有否定路径必须在写操作前停止。独立审查与最终 HEAD CI 全部通过后合并，再执行本次明确授权的恢复。
