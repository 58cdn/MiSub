# 检测器一键安装与发行能力

配对入口只针对具备所需能力且已经发行的客户端提供安装命令。`probe-v0.1.0` 不具备 `--pair` 和用户级安装命令，不能用于当前配对流程。兼容版本未发行时，界面明确展示不可用状态，保留高级手动配置入口。

默认复制入口采用[固定版本短网络命令](detector-network-install.md)：完整下载并验证已发行脚本后，在内存交接给原安装器。

## 交付分界

1. 发行能力：受校验的公开发行目录绑定版本、源码提交、平台、固定资产 URL、长度与摘要；管理接口与界面使用同一目录。未知、读取失败或缺少平台资产时不创建安装窗口、不生成安装命令。
2. 引导安装：Bash 支持 Linux/macOS amd64、arm64；PowerShell 支持 Windows amd64。脚本识别架构，下载锁定的独立可执行文件，核验长度、SHA256 和客户端能力后，使用绝对路径完成配对、配置校验、用户级安装与显式启动。
3. 正式发行：先验证完整源码、构建输入、许可材料、产物绑定与来源，再经明确手动触发发布新版本。已有发行资产保持不变。网页仅在核实新发行资产与能力后启用对应命令。

## 状态与恢复

网络下载采用有界超时与有限重试。配对兑换不自动重试；过期窗口需要用户返回网页重新准备。已有私密配置受保护，显式恢复模式只核验和继续安装启动，不重新兑换身份。安装或启动失败时保留已写入配置并展示可执行的恢复路径，不删除已有身份或凭据。

脚本无需额外安装 Go、Node.js、Python、Docker 或代理内核，不假设当前目录已有检测器。使用平台现成的 shell、HTTPS 下载和摘要能力；缺少前提时明确失败。脚本不设置登录自启、系统代理、TUN、提权或公网监听。

## 验收

默认使用离线 fixture、临时目录与进程验证架构映射、下载损坏、超时、不可用发行、路径与现存配置保护、过期配对和恢复。独立审查及最终 HEAD CI 通过后按仓库规则合并；合并与 Pages 部署不等同于正式客户端发行或真实机器验收。
