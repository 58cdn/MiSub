# 检测结果的执行声明快照

任务结果与检测器历史接口通过 `executionMetadata` 返回该任务完成时接受的检测器声明。快照与该次结果一起保存；检测器之后升级、更换名称或再次领取任务，不会改变既有结果。这里的“完成”包括检查结果失败，但不包括未提交结果的失败尝试。

声明来自检测器，并非远程证明。`kernelLockVersion` 表示构建内嵌锁文件声明的版本，不证明该任务实际启动过内核，也不替代发行资产校验。`format` 等不需要内核的检查也可携带该字段。快照不参与任务能力协商。

## 请求与返回

检测器在执行任务前构造一次声明，将其作为 `POST /api/probes/v1/agent/tasks/{id}/result` 请求的可选字段，与 `leaseToken`、`checks` 并列。结果重试使用同一份检查结果和声明，不重新执行任务。

```json
{
    "leaseToken": "<leased token>",
    "checks": { "format": { "status": "passed", "code": "ok" } },
    "executionMetadata": {
        "schemaVersion": 1,
        "wrapperVersion": "0.0.1-alpha.1",
        "wrapperRevision": "<实际完整40位小写SHA>",
        "buildChannel": "development",
        "sourceState": "clean",
        "platform": "linux-amd64",
        "kernelLockVersion": "v1.19.32",
        "ruleSetVersion": 1
    }
}
```

示例版本仅用于说明协议，不表示已发行版本；SHA占位符必须替换为构建的实际完整源码修订，不能作为真实请求发送。

| 字段                | 含义与限制                                                                                               |
| ------------------- | -------------------------------------------------------------------------------------------------------- |
| `schemaVersion`     | 声明结构版本，当前为整数 `1`。                                                                           |
| `wrapperVersion`    | 检测器产品版本，长度不超过64；新测试构建为 `0.0.1-alpha.N`，不携带显示SHA后缀，历史构建身份保持可读。    |
| `wrapperRevision`   | 实际40位非全零小写SHA；历史构建标记 `source` 保持可读，新alpha不以其代替源码身份。                                                 |
| `buildChannel`      | 可选 `development` / `testing`，缺失保持未知，不用当前安装资料补齐历史。                                 |
| `sourceState`       | 可选 `clean` / `dirty` / `unknown`；只有干净、已知的完整源码身份可派生开发显示，客户端自报不是来源证明。 |
| `platform`          | `linux-amd64`、`linux-arm64`、`darwin-amd64`、`darwin-arm64`、`windows-amd64`。                          |
| `kernelLockVersion` | 可选的内嵌锁版本，长度不超过 64，可带 `v` 前缀；未知时省略。                                             |
| `ruleSetVersion`    | 1–65535 的整数，标识检测器判定规则基线。                                                                 |
| `source`            | 只由服务端在保存与返回时固定为 `detector_reported`，客户端输入不能覆盖。                                 |

字段白名单不包括主机名、本地路径、原始错误、节点配置、凭据或任意构建环境内容。服务端丢弃未知字段；已知字段不合法时返回固定的 `400 invalid_execution_metadata`。整个声明省略或为 `null` 表示未知。原生检测器发现构建版本、修订或平台不合法时省略整个声明；仅内核锁版本不合法时省略该字段，仍可正常提交结果。

`GET /api/probes/v1/jobs/{id}` 的 `data.nodes[]` 与 `GET /api/probes/v1/agents/{id}/history` 的 `data.records[]` 在原有 `checks` 旁返回 `executionMetadata`。排队、未完成、旧版本写入或存储声明不完整的记录返回 `null`；接口不会用当前 agent 资料补齐历史。完成时间仍取原有 `completed_at` / `completedAt`，尝试次数仍取任务的 `attempt`。七天保留期与清理逻辑保持适用。

## 重试与存储兼容

首次完成使用原有租约 CAS，在同一次更新中保存检查结果和声明。错误租约、已过期首次提交、取消或撤销的任务不能留下已完成结果或声明。已完成结果的正常重复确认沿用原租约和检查摘要判定，观察时间始终基于首次完成时间。

已保存有效声明的记录，仅在规范化后的声明相同时接受重放；字段顺序与被丢弃的未知字段不影响相等性。缺失或变更声明返回 `409 execution_metadata_conflict`。已有旧记录没有声明时，合法重复结果仍可确认，但不会补写声明。非法声明在旧记录重放时仍返回 400。

存储继续使用现有 `probe_tasks.result_json`，不新增表或列。顶层保持旧版 checks 对象，每项 Check 的扩展字段保存相同的声明副本，最多六份。新服务端读取时移除各 Check 的副本，统一返回记录级声明。只有全部副本存在、合法且规范化后一致，才视为有效快照；部分缺失、非法或矛盾的副本返回未知，并拒绝重放，避免被误当成旧记录。

`result_hash` 继续覆盖原本规范化后的 **checks**，并不覆盖带声明副本的完整 `result_json`。它用于旧版结果幂等确认，不证明声明真实性。声明的一致性由新服务端另行比较。

| 组合                  | 行为                                                                                                             |
| --------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 旧检测器 → 新服务端   | 正常接受；声明未知。                                                                                             |
| 新检测器 → 旧服务端   | 旧服务端忽略请求 sibling 字段，正常接受；声明未知。                                                              |
| 新服务端 → 已有旧记录 | 正常读取与确认；不回填声明。                                                                                     |
| 回滚服务端 → 新记录   | Check 扩展字段保留旧读取格式，checks-only 摘要保留旧确认方式；旧服务端不检查声明是否相等，但不会改写已完成快照。 |

回滚兼容的固定验收基线为 `7f794ec5fb6ab0b5cc51e75f1f24334035355bbc`。不能由此推断任意历史版本均兼容。metadata 必须放在请求的 sibling 字段；尤其 observations 请求继续严格校验 check 字段，不接收存储内部扩展。

## 管理界面

在检测器历史记录或远端任务结果中展开“历史执行声明”，可查看该次结果的检测器版本、源码修订、构建平台、内核锁版本声明、判定规则集版本与声明结构版本。来源固定标为“检测器自报”，只说明该次结果携带的信息；当前检测器升级、改名或再次领取任务不会补齐历史字段。本地格式检查不显示检测器执行声明。

| 记录情况                         | 展示                                                               |
| -------------------------------- | ------------------------------------------------------------------ |
| 已完成且声明可识别               | 已记录；各检查仍按其成功、失败或超时结果显示。                     |
| 已完成但声明为空或缺失           | 无可用记录；可能未记录，也可能存储内容无法读取，当次版本保持未知。 |
| 声明结构、来源或已知字段无法识别 | 未知；不显示原始字段。                                             |
| 排队或运行中                     | 尚未记录；等待完成结果。                                           |
| 已取消或过期                     | 未记录；未收到完成结果。                                           |

可识别声明未提供内核锁版本时，显示“未知（未提供）”；源码修订为 `source` 时，显示“源码构建，修订未提供”。界面只读取声明字段白名单，不回显额外属性、路径、凭据或原始错误。声明不表示当前能力、解锁通过或实际内核执行证明，也不参与任务调度。

干净且具有实际完整源码SHA的开发构建显示 `0.0.1-alpha.N.sha.<SHA前12位>`，同时保留产品版本与完整修订可查。dirty/unknown或缺少构建通道的历史记录不能被补造为可信开发身份。测试通道的升级比较仅使用产品版，按数字比较N，SHA不参与排序；旧稳定系列需要显式迁移，不能因其基础数字较大被自动推荐。

展开控件使用原生键盘交互，兼容中英文、深浅色与窄屏长版本信息。历史切换和任务结果分页沿用现有请求隔离及状态刷新逻辑。

## 规则集版本维护

`detector/execution_metadata.go` 中的 `executionRuleSetVersion` 从 `1` 开始。改变状态、错误码、服务判定、来源证据解释或测量含义时，应递增该整数，并更新相应测试与更新日志；纯展示或传输实现修复不必递增。结构不兼容变更另行演进 `schemaVersion`。这两个版本都独立于 observations 的 `probeVersion` / wire schema，不得互相推断。

当前快照只覆盖最终被接受的一次完成结果，不记录每次失败尝试，也不提供 agent 最近能力、独立心跳时间或能力历史。[领单声明与续租记录](probe-agent-runtime.md)使用独立的 probe 存储结构和分阶段开关，不由结果快照反推。

完整字段定义见 [OpenAPI](node-probes.openapi.yaml)，使用入口见 [节点检测操作说明](node-probes.md)。
